1What it does today

A fast, scriptable, read-only CLI for the PCE. It speaks JSON to agents and tables to humans.

Every command below is real and merged on main. Output is a table when you are at a terminal and JSON when stdout is piped; force either with --table or --json. Nothing in this release can change your PCE: it is read-only by design.

# connectivity, objects, workloads
$ illumio-tui health
$ illumio-tui labels --key app
$ illumio-tui label-groups
$ illumio-tui iplists
$ illumio-tui services
$ illumio-tui workloads --label app=web --online true

# policy, draft by default, every href resolved to a name
$ illumio-tui policy rulesets
$ illumio-tui policy rules "Web-DB"
$ illumio-tui policy pending

# Explorer traffic: flows, app-to-app, blocked
$ illumio-tui traffic query --window 24h --src app=web --dst app=db --json
$ illumio-tui traffic query --window 1h --group app,env
$ illumio-tui traffic query --window 1h --blocked
$ illumio-tui traffic query --window 30d --dry-run

# connection profiles
$ illumio-tui profile list
$ illumio-tui profile use prod

Explorer, without the clicking

traffic query runs the PCE's asynchronous Explorer query for you: it submits, polls with backoff, downloads, flags truncation, and resolves every label href to key=value.

Filters read like you think: app=web, ip:10.0.0.5, ipl:NAME, wl:HOST, fqdn:NAME. A comma means AND, repeating the flag means OR. Add --exclude-src, --exclude-dst, --port, --proto, --process and --decision as needed. An unknown label value fails locally, before the PCE sees anything.

--group app,env folds flows into app-to-app pairs with allowed, potentially blocked and blocked counts. --blocked keeps only blocked and potentially blocked flows, grouped by destination and port. Both run on the downloaded result, with zero extra requests.

Built for agents

Underneath: the pce library

The CLI is a thin layer over a standalone Rust crate with no terminal code in it: a throttled HTTP client with backoff, a TTL cache, typed models checked against anonymised recordings from a real PCE, the async Explorer poller with cancellation, href-to-name resolution, and the label-pair and blocked aggregations. The TUI will reuse every piece of it.

2Gentle on the PCE, by construction

Your PCE is shared, expensive and important. This tool treats it that way.

Most tools that hammer a management plane do it by accident: a refresh loop nobody asked for, a retry storm, an Explorer query over ninety days that someone fired off to see what happens. illumio-tui is built so that none of that can happen quietly. Every request is caused by you, throttled, cached where it can be, counted, and shown back to you.

  • 2 req/s, burst 5One token bucket shared by every request. 429 and 503 pause the whole client with exponential backoff and jitter, honouring Retry-After. POSTs are never retried.
  • Counted, alwaysEvery call and every byte goes into meta.api_calls and meta.bytes. You always know what a command cost.
  • Cached 15 / 5 minLabels, label groups, IP lists and services for 15 minutes; policy and workloads for 5. One traffic result set is kept until the filter changes.
  • 24 h, 1000 rowsExplorer queries default to a 24-hour window and a 1000-row cap. Truncation is always reported.
  • --yes above 7 days or 10 000 rowsExpensive queries stop with exit code 2 and tell you why, until you confirm on purpose.
  • --dry-runPrints the exact Explorer request body and sends nothing to the PCE. See the query before the PCE does.

3What's next: the TUI

in progress, not shipped yet

Explorer, policy and inventory in one keyboard-driven screen, in the spirit of btop.

The interactive terminal UI is the next plan. Boxed panels with titled borders, dense stats, decision bars, one dark and one light palette. It sits on the same library the CLI already uses, so every protection above carries over unchanged. Run illumio-tui with no subcommand today and it tells you the TUI is on its way.

Concept of the Traffic screen in its app-to-app view, drawn from the design spec. Final layout may differ.

Four screens

  • 1Traffic. One filter, one query, three views on v: the flow table, the app-to-app aggregate with a drill-down on enter, and a blocked focus grouped by destination and port.
  • 2Policy. Rulesets on the left, resolved rules on the right, deny rules in their own section, draft and active on d, pending changes on p.
  • 3Labels & objects. Labels, label groups, IP lists and services, with cache age shown and per-type refresh.
  • 4Workloads. Enforcement, visibility, online state, VEN status. t jumps to Traffic with that workload as source.

Still gentle

  • A : command prompt: :traffic, :filter, :window, :profile, :draft, :active.
  • View switches, sorting, searching and grouping never re-query.
  • Auto-refresh is opt-in per screen with a, never faster than every 60 seconds, and it shows a countdown.
  • The API call count and byte count live in the header, all the time.

4How it was made

The design was written up as a spec and approved before any code existed. Implementation then followed a task plan, and every task was implemented and then independently reviewed before the next one started. AI coding agents in Claude Code did the implementation and review work, under the owner's direction. The result: 103 automated tests, clippy and cargo-deny clean, and a live smoke test against a real PCE that returned 50 flows in 9 API calls. The design spec, implementation plans and architecture notes are all in the repository.

5Install

You need a stable Rust toolchain and an API key for your PCE. Build from source:

$ git clone https://github.com/alexgoller/illumio-tui
$ cd illumio-tui
$ cargo install --path crates/illumio-tui

Configure with environment variables

The same names as illumio-mcp-server, so an existing setup just works:

PCE_HOST=pce.example
PCE_PORT=443
PCE_ORG_ID=1
API_KEY=api_xxxxxxxxxxxx
API_SECRET=xxxxxxxxxxxxxxxx

PCE_TLS_VERIFY is honoured too. --env-file .env loads a dotenv file for a single run.

Or with profiles

In ~/.config/illumio-tui/config.toml:

default_profile = "prod"

[profiles.prod]
host = "pce.example"
org_id = 1
api_key = "api_..."
api_secret_cmd = "op read op://vault/pce/secret"

api_secret_cmd fetches the secret from your password manager at run time. Switch with profile use or --profile.

Per-run overrides: --host, --pce-port, --org-id, --profile, --config, --insecure, --no-cache. The connection port flag is --pce-port because traffic query has its own --port filter.
